## The thinker (spine, handles, limits)

- **[T:thesis]** One shift runs through the corpus: the thing that decides how a system behaves is moving out of source code. Software 1.0 is explicit instructions; in Software 2.0 "the source code comprises 1) the dataset that defines the desirable behavior and 2) the neural net architecture," with the weights filled in by training, so in his compression, "Software 2.0 is code written by the optimization based on an evaluation criterion." The practical consequence he draws is a change of job: when the network fails on a hard case, "we do not fix those predictions by writing code, but by including more labeled examples of those cases," and most of the active development becomes "curating, growing, massaging and cleaning labeled datasets." This page reads vibe coding as the cheap version of the same move, made at the keyboard instead of in the training loop. The model writes the source, the person stops reading it, and what gets traded away is comprehension of an artifact that does still exist in a repository. He named that trade with some enthusiasm for throwaway work, and has since reported in detail where coding models stop helping him.

- **[N:simon-willison:thesis]** Simon Willison's thesis: Prompt injection, in Willison's definition, is what happens when an application concatenates a developer's trusted instruction with untrusted text and the model acts on the combination. He treats that as the reason the defenses built for older injection attacks have no equivalent here: SQL injection has a known mitigation that is guaranteed to work, in escaping and quoting user-provided strings, and no such function exists for natural language. From there he draws a rule about what a fix may be made of. A hole patched with another model cannot be verified, because the model is a black box and an adversary keeps trying until something works, so the direction he trusts is architectural, keeping untrusted content away from anything that holds privilege. His claim about the state of the art is narrower than the rule, and he states it plainly: two and a half years into the problem he had seen alarmingly little progress toward a robust solution, and nobody yet knows how to prevent it 100 percent reliably.

- **[N:kent-beck:thesis]** Kent Beck's thesis: Software costs what changing it costs. Beck states that as Constantine's Equivalence, cost(software) ~= cost(change), and credits the coupling and cohesion work in *Structured Design* for the underlying result. ## Current reading (input only when redrafting, not a source)

> Karpathy's 2017 essay splits programs by where their behaviour is written down. Software 1.0 is explicit instructions; in Software 2.0 the weights carry it and "no human is involved in writing this code." The mechanism is one sentence: "Software 2.0 is code written by the optimization based on an evaluation criterion." The work moves to the criterion and the data, so a failure on a hard case gets fixed by adding labelled examples of it. Seven years later he coined vibe coding, where the model writes the source and the person stops reading it. The two name different artifacts: one has no source to read, the other has source nobody read. The definition people argue about is Willison's narrowing rather than his. His own account carries the limits, from the essay's trade between accuracy and understanding to his report in October 2025 that on code where "everything has to be very precisely arranged" the models were "just not net useful."

> The comprehension crisis is usually counted as one gap, measured in the volume of code nobody has read. His distinction splits that gap in two, because the artifacts fail comprehension in ways that need different controls. Unread generated source stays readable, so that gap has a price in review, tests and provenance. A trained model's behaviour is written nowhere a reviewer can go, so semantic comprehension lives in the evaluation criterion and the dataset or nowhere. An organization running one assurance policy over both buys review where review is available and calls the rest covered. Whoever holds the criterion for the second kind holds its behaviour, which is a different accountability from owning a repository. The split works only where the criterion can be stated: an owner for it, an evaluation set controlled like code. The risk is the adversarial examples his essay's limitations section names: a criterion passed on a held-out set says nothing about attacker-chosen inputs.
