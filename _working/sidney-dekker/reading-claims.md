# Reading claims: Sidney Dekker

Protocol v1. One line per sentence of `reading` and `extension`, each with the grounding-pack IDs it rests on.

## reading

- Dekker's starting point is that human error is a consequence of system conditions, so the investigator's job is to reconstruct how an action made sense to the person at the time. [T:thesis] [F:new-view-of-human-error]
- If it made sense once, it will make sense to the next person in the same position. [T:thesis]
- Just culture draws the accountability line: people answer for willful violations, while honest mistakes and system-induced failures become material for learning. [F:just-culture]
- Drift into failure explains how organizations reach unsafe states through many small, reasonable choices toward efficiency, none of them obviously wrong. [F:drift-into-failure]
- The frame works best when used surgically, because invoking drift for every incident can close off the question of which decisions could have gone differently. [L:2]

## extension

- Security programs drift the same way, one reasonable exception at a time. [F:drift-into-failure]
- Each risk acceptance makes sense on the day it is signed, and the unsafe state appears only in the accumulation. [F:drift-into-failure] [T:thesis]
- Recording every exception as a structured, auditable object with an owner and an expiry makes that accumulation visible before an incident does. [P:6]
- An expiry helps only if renewal demands a fresh justification, since routine renewal turns the record into a paper trail of the drift. [F:drift-into-failure]
- Just culture then shapes the review, which asks how each acceptance made sense at the time while still separating an honest call from a willful violation. [F:just-culture] [T:thesis]
- The register cannot stop drift by itself, and it does stop the organization from being the last to notice what has accumulated. [F:drift-into-failure] [P:6]
